Per-song priced checkout — order form, charge wiring, and payment hardening

Date: 2026-07-02.

With the pricing module approved and finalized in the morning session, the checkout slice went live the same day. A migration added the order fields to the projects row — song count, stem count, the quoted subtotal, and the client's reference-track notes — with check constraints, riding the existing row-level policies; it was applied to the remote database and verified there. The Project type moved those fields into its required-nullable block in the same change.

The order form grew from a title-notes-upload shell into a real order surface: a service picker over the existing format column (Dolby Atmos, binaural, or both, replacing a hardcoded value), a song-count input, a reference-tracks field, and a live quote that recomputes from the pure pricing module as the count changes — showing the per-song line, the automatic album discount when three or more songs are ordered, and the estimated total. The stem count is deliberately not a free-typed number: it is captured at checkout from the files the client actually selected, so the order record can never disagree with the upload. The upload-timing question the issue asked to settle explicitly is now documented in the code: stems are chosen before payment but upload only after the payment confirms, which the server independently enforces by refusing stem registration until the project is out of its pending-payment status.

The checkout route now validates the order, prices it through the pure module, creates the payment intent for the computed total, and persists the order fields; the payment step renders the same breakdown line by line. The one-shot first-mix discount survived the switch by riding through the module as a private fifty-percent code — private so it does not stack with the bulk tier, and bounded by the two-hundred-twenty-five-dollar floor exactly as the approved guard rails intend. Because the bulk tier, its display, and its tests all shipped inside this slice, the separate bulk-discount issue closed with it.

A twenty-eight-agent adversarial review of the diff confirmed twenty-three findings before commit, and the fixes landed with the slice. The Stripe client is now resolved before the discount reservation, so a configuration failure can no longer silently burn a customer's one-shot discount; redirect-based payment methods are disabled on the intent because a redirect would destroy the in-browser file list before the post-payment upload; the payment-status poll survives transient network failures instead of freezing the page; and the form guards against malformed checkout responses instead of quietly re-enabling itself. The review also surfaced two pre-existing holes that the new pricing made materially more valuable to abuse, and both were closed at the database level in a hardening migration: the first-mix RPCs now require the caller to be acting on their own account (or be studio), restore is refused outright once any paid order has consumed the discount, and a trigger freezes the money and order columns against client updates while leaving the service-role webhook and studio untouched. A leftover unpriced project-creation endpoint — a route with no callers that would have let any signed-in user mint an uploading project without paying — was removed, and the legacy flat-price function it dated from was deleted with its tests, since the live checkout no longer calls it.

Coverage moved with the behavior: the checkout route suite grew to twenty-six tests spanning single- and multi-song pricing, the floor-bounded first-mix path, bulk suppression under private codes, validation edges, and every rollback-and-restore branch, and the order form and payment step gained their first component tests — the live quote, the derived stem count, the submitted payload, and the itemized breakdown. The full suite stands at four hundred seventy-seven tests, with lint, types, and the production build clean. Architecture and agent docs were updated to describe the new payment flow and to stop calling the per-song work planned; the one remaining consistency gap is marketing copy, which still advertises the old fifty-percent promo until its replacement slice lands.
