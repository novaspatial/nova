# Per-song priced checkout

Date: 2026-07-02

Goal: make checkout charge the real per-song price — order form, live quote, and Stripe charge all running off the approved pricing module — and harden the payment path while touching it.

A migration added the order fields to projects (song count, stem count, quoted subtotal, reference-track notes) with check constraints, applied and verified on the remote; the Project type moved them into its required-nullable block. The order form grew from a title-notes-upload shell into a real order surface: a service picker (Dolby Atmos, binaural, or both), a song-count input, reference tracks, and a live quote from the pure pricing module — per-song line, automatic album discount at 3+ songs, estimated total. The stem count is never free-typed: it's captured from the files the client actually selected, so the order record can't disagree with the upload. Stems are chosen before payment but upload only after it confirms, enforced server-side by refusing stem registration while the project is pending payment. The checkout route validates, prices through the module, creates the intent for the computed total, and persists the order; the payment step renders the same breakdown. The first-mix discount rides through as a private 50% code — private so it doesn't stack with the bulk tier, bounded by the $225 floor — and the bulk tier shipped inside this slice, closing its separate issue.

A 28-agent adversarial review confirmed 23 findings, fixed before commit: Stripe is now resolved before the discount reservation (a config failure can no longer silently burn a client's one-shot discount), redirect payment methods are disabled on the intent (a redirect would destroy the in-browser file list needed for the post-payment upload), the payment-status poll survives transient network failures instead of freezing the page, and the form guards against malformed checkout responses. 2 pre-existing holes the new pricing made worth abusing were closed at the database level: the first-mix RPCs now require self-or-studio and refuse restore once any paid order consumed the discount, and a trigger freezes the money and order columns against client updates while leaving the webhook and studio untouched. A caller-less endpoint that could mint an uploading project without paying was deleted, along with the legacy flat-price function and its tests.

Coverage moved with the behavior: the checkout suite grew to 26 tests (single- and multi-song pricing, the floor-bounded first-mix path, bulk suppression under private codes, validation edges, every rollback branch), and the order form and payment step gained their first component tests. Suite at 477, lint/types/build clean; architecture and agent docs updated to the new flow. 1 known gap: marketing still advertises the old 50% promo until its replacement slice lands.
