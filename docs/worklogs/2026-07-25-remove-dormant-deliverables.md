# Remove the dormant deliverables pipeline

Date: 2026-07-25

Goal: settle #13 (admin file download) and stop carrying infrastructure nothing uses. Investigation showed #13 was already satisfied. Its stems half has been live for a while: the studio can open any project in the portal and download its stems (UploadManager's studio-only download button over stemDownloadRoute, "studio sees all" RLS underneath). Its deliverables half had nothing to download: no UI ever called the deliverables table, the project-deliverables bucket, or their 4 API routes, and the 'deliverable' file type was unwritable — the files route accepts only stem/master_ref/mix. Delivery in practice is mix files on the Listen page. So #13 closed as already-live, and the dead pipeline was removed instead of built out.

The code removal (90c1f82, −868 lines) deletes the 4 deliverables routes and strips the 'deliverable' kind from the #35 storage seam, uploadRunner, projectCleanup, requireProjectChild, and the portal types. It also deletes the PATCH deliverable_format side-write, which was a silent no-op in production: the table had no UPDATE RLS policy, so the update always matched 0 rows. signedDownload now always forces the stored file name. Lint clean; 817 tests in 69 files pass.

The DB half is 20260725_remove_deliverables.sql, applied to the remote after the Vercel deploy went live (old code tolerates the missing table; the reverse order doesn't hold). The remote was verified empty first — 0 rows, 0 bucket objects, 0 tagged files — and the migration guard-aborts if a replay ever finds data. It drops the table (its 3 RLS policies go with it), the 4 project-deliverables policies on storage.objects, and the bucket row, then narrows the file_type CHECK to the 3 real values. 1 gotcha: Supabase's storage.protect_delete() trigger rejects direct deletes from storage.buckets, so the migration sets the transaction-local storage.allow_delete_query opt-in first (fix in 2d27502).

Ripples: D7's recorded purge scope says "stems and deliverables both"; with the table gone, that maps to stem + mix rows via projectCleanup — noted on #27 for confirmation at pickup, D7 itself unamended. CONTEXT.md keeps Deliverable as the business term for the signed-off mix files the client downloads from Listen.
