# Driving the launch residue — #44, #45, #50, #51, #54, #55, #59

Date: 2026-07-31
Goal: take the seven issues the 2026-07-30 sweep left open — all framed as gated on a human — and finish whatever was actually finishable.

## The framing was half wrong

Reading every issue thread against the repo and the live database, rather than trusting the handoff, found that only 4 of the 7 were genuinely human-gated. #59 was still labelled `ready-for-agent` and held 6 shippable code items, and 3 more defects sat inside code already reported done. The worst was in the discount seam: `reserve_first_mix_discount` and `restore_first_mix_discount` were EXECUTE-able by `anon` — Supabase's default function privileges were never revoked in 20260422 — and their 20260702 identity guards deliberately pass when `auth.uid()` is null so service contexts can call them. An anonymous caller had both halves. The pre-migration probe confirmed it: `POST /rpc/reserve_first_mix_discount` with an arbitrary uuid returned 200 from an anon key. That is a stranger burning a client's welcome discount, or re-arming their own. All six discount RPCs are now service_role-only, the code moved first and drained before the revoke (migration-first would have 500'd every no-code checkout), and the same probes return 42501 after. The other three: the contact limiter interpolated the submitter's address into PostgREST's comma-delimited `or=` grammar while `EMAIL_PATTERN` admits commas, so `a,ip_hash.eq.0@x.com` split the filter and the only bound stopped binding; production shipped no `Reporting-Endpoints` header at all, because `csp.ts` reads `NEXT_PUBLIC_SITE_URL` raw and it is unset in the Vercel build env, leaving half of #50's evidence channel dark; and the public `blog-assets` bucket had a broad SELECT policy that let anyone enumerate it.

## What shipped

7 commits, 862 → 1015 tests, 4 migrations applied to production. Beyond the four fixes above: Sentry wired DSN-gated across server, edge and browser, so it ships completely inert and setting the DSN in Vercel is the whole activation, with `alertMoneyPathAnomaly` on all four Stripe-metadata mismatch branches — a tamper signal on the money path that previously log-and-200'd into a log nobody reads. An orphan sweeper on a second daily cron, which needed a new `upload_registered_at` column: `created_at` could not serve, because #57 made registration idempotent and a re-upload flips an old row back to `pending` without touching a timestamp, so a sweep keyed on `created_at` would have deleted a live re-upload's row and object out from under it. Its second half — comment-attachment objects that never became rows — runs as a service-only SQL anti-join, since `storage.objects` is unreachable from PostgREST and one exact query beats paginating a bucket. The footer newsletter form, which promised a 15% discount and was wired to nothing, now forwards to signup with the promo token exactly like the promo popup. Plus the archive fence's missing null-uid escape, the package name and engines, the unused `STRIPE_RESTRICTED_KEY`, a purge-backlog warning, and dev-bypass regression guards asserting one env reader and a never-armed `.env.example`.

ADR 0002 restores the D-series rulings that only survived in git history — their absence had already left a comment in `terms/page.tsx` telling readers not to write refund copy because "D-refund open", when D-refund was answered on 2026-07-14. #60 was filed for the nonce half of #50, deferred at the time to "its own issue" that was never created.
