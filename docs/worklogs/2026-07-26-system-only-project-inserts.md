# System-only project inserts

Date: 2026-07-26

Goal: close the 2 insert-fence residuals from the #40/#41 hardening — #42 (deleting a paid project frees its unique Stripe intent id for re-attachment to a fresh `pending_payment` row) and #43 (direct PostgREST inserts skip the checkout rate limit and consent gate, can be born archived/deleted, and since #26 can stamp `applied_coupon_code` without a hold) — as one slice. Both lived inside the same allowance: the 20260708 fence let client sessions create rows as long as they were born unpaid. Rather than policing row shape harder (intent tombstone, DB rate bound, column pins), the slice removes the allowance. The Stripe-branch checkout insert moved to the service client (13908d3; the dev-bypass insert has run there since #40), and `20260726_system_only_project_inserts` replaces the fence with a full reject — non-studio client INSERTs on projects 42501 outright. With the UPDATE path frozen since 20260702, no unprivileged writer of `stripe_payment_intent_id` remains, and every #43 vector required exactly the INSERT the fence now refuses.

2 deliberate calls, plus 1 operational note. Consent and the 3/min rate limit stay route concerns: `TERMS_VERSION` is a deploy-time constant the DB can't know, and with client inserts gone every surviving row necessarily passed the route's gates — nothing DB-reachable is left to bound. The service insert trades RLS's WITH CHECK owner pin for the fence: `owner_id` still comes straight from `requireApiUser`, and the happy-path test pins it — the same posture the dev-bypass insert has had since #40. Operationally, `SUPABASE_SERVICE_ROLE_KEY` is now required for every checkout, not just dev-bypass/catalog-code paths (a missing key fails loud with a 500 before any side effect), and deploy order mattered: code pushed and the Vercel deploy confirmed first, fence applied after, because the old client-session insert dies on the new fence.

Suite 861 (1 net new test; ~20 checkout tests rewired onto a suite-level service projects chain), lint green, no type change (no schema columns touched — the RLS+types rule is satisfied vacuously). The fence is proven on the remote, not just in mocks: a simulated authenticated insert dies 42501 with the fence message, a sessionless insert passes (rolled back), the 20260708 trigger/function pair is gone, and the 4 sibling fences are intact. Advisors show no new class — the definer-function EXECUTE warning now attaches to the renamed fence function exactly as it already does to its 4 siblings.
