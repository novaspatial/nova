# Launch-readiness sweep — issue-loop over #44–#59

Date: 2026-07-30
Goal: build a loop between `devplan.md` and the GitHub tracker, then run it until every issue an agent can close is closed.

## The loop itself

The mechanism is a repo skill, `issue-loop`, living at `.agents/skills/issue-loop/` with the usual `.claude/skills/` symlink (both gitignored, like the 17 vendored skills; it stays out of `skills-lock.json` because it has no upstream). `SKILL.md` carries the algorithm, `VERIFY.md` the gate chain and the adversarial-RLS probe recipe, `PLAN-TEMPLATE.md` the issue-comment formats. Its state model is three sources with one job each: `devplan.md` for ordering, batching and exit gates; the issue plus its agent brief as the per-issue contract; `main` for what actually shipped — brief beats devplan beats loop judgement. Per unit it plans, posts the plan to the issue, implements, verifies, commits, closes, and refreshes the devplan inside the same commit. Every comment it posts opens with `> *This was generated by AI while working the issue.*`, the working-loop sibling of the triage disclaimer. Four rules were settled up front with the user: the loop does the technical half of human-labelled blockers and leaves them open with an ops checklist; it never touches legal or marketing issues; migrations go to the live database through MCP; commits go straight to `main` with no co-author trailer. `devplan.md` was untracked, so the first commit put it under version control — a dashboard that isn't in git can't be the tracker's counterpart.

**#45** — `isPaymentsDevBypassEnabled` forces the payments bypass off when `VERCEL_ENV` is production (or `NODE_ENV` off Vercel), so Vercel previews keep working; `.env.example` no longer ships the flag armed. **#44** — a `SECURITY DEFINER` fence on `profiles.role`, `first_mix_discount` and `email`, plus grant narrowing: the issue's proposed column `REVOKE` was a no-op because column privileges were never granted separately, so the table-level UPDATE grant was replaced by `GRANT UPDATE (display_name, avatar_url, updated_at)`. the self clause is load-bearing, since every other table's studio subquery reads the invoker's own row, and studio rows stay readable so comment authorship keeps rendering. **#48** — paid projects can no longer be deleted by their owner, gated in the handler and at the DB floor, with the storage sweep moved after the row delete (paths collected before it, because the child rows cascade). **#49** — status notifications became best-effort like the receipt sender. **#56** — `safeNextPath` at all three `next` consumers, including the login page where `router.push` hands a protocol-relative href to `window.location` and the reported exploit actually leaves the origin; ## How it was verified

Every authorization fix ran a **pre-migration positive control** — the exploit executed inside a transaction that always rolls back, proving the probe valid before the fix made it fail. Escalation to studio succeeded before and was denied after, at both layers independently; foreign-project comment injection likewise; anon read 3 profile rows before and 0 after; a paid project deleted cleanly before and raised 42501 after. Allowed paths were checked with the same rigour: self-read and self-rename, studio-row visibility to clients, studio seeing everything, unpaid client delete, studio paid delete, comment and attachment survival after a mix delete. Per unit the chain was lint, `npx vitest run`, `npm run build`, `get_advisors(security)` after DDL, then CI on `main`. Advisors now show no ERROR-level findings, and the `rls_policy_always_true` warning on `contact_inquiries` is gone. Planning for the seven Phase 2 issues ran as a parallel fan-out of read-only agents while earlier units were building; implementation, database writes and pushes stayed strictly serial.

**One mistake worth recording:** `npm run build | tail` masks the build's exit code, so a commit that broke the type-check reached `main` (fb52463, from #58's nullable `track_id` flowing into a comment count). It was caught and fixed minutes later in 921d01a, and CI is green there. Every gate run after that used `set -o pipefail`.
