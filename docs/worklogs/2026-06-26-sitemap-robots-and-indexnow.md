Sitemap, robots, and IndexNow notification for the blog

Date: 2026-06-26

Built the next two pieces of the blog and SEO automation work on top of the foundation from earlier in the day, in the requested order: first the sitemap and robots file, then the search-engine notification.

Sitemap and robots. The site now serves a machine-readable sitemap listing the marketing pages and every published blog post, plus a robots file that points crawlers at it. The sitemap is drawn from the same published-only query the blog index and post pages render with, so it can never advertise a post the site would 404, and drafts never appear; each post carries a last-modified date from its update time, and every address is absolute, built from the single canonical-host source. The robots file allows the public site and disallows the whole non-public surface — the APIs, the auth routes, the client portal, and the blog admin — and names the sitemap location. The robots file is static; the sitemap is generated per request so it is always fresh the moment a post is published or taken down.

IndexNow notification. Publishing, updating, or taking down a post now quietly tells the participating search engines to recrawl. It hangs off the single publish hook built earlier rather than off any individual save path, and it is best-effort by contract: it never blocks or breaks the publish action, never throws, and does nothing at all until a key is configured, so dev and preview environments stay silent. A post that was never public never triggers a ping; to make takedowns work the publish hook now also tracks whether the post was live before the change, so unpublishing or deleting a previously-live post still notifies the engines that its URL is gone. The verification key is served from one place, driven by an environment variable, and referenced back to that location in each ping so the key never has to be duplicated. This lightweight path reaches engines such as Bing, Yandex, Seznam, Naver, and Yep; Google does not participate in it and relies on the robots file and sitemap instead, which is noted in the code so expectations stay correct.

Co-located tests cover the sitemap and robots output, the notification module (no-op without a key, correct payload, failures logged but never thrown), the key endpoint, and the publish hook's full fire-or-skip matrix across publish, edit, unpublish, delete, rename, and draft cases. The whole suite, lint, and the production build all pass; the build registers the new sitemap, robots, and key routes.
