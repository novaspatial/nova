Blog image-source decisions and per-post SEO metadata

Date: 2026-06-26

Settled two open questions about where blog post images come from, then built the per-post SEO surface on top. For the hero and social image, a post now reuses the first image in its body (via the existing extractHeroImage), and falls back to the site-wide default when it has none. This avoids a new database column or editor field: the social image is just the picture the page already shows, and resolvePostOgImage keeps an explicit fallback chain so a dedicated column could be added later without reworking callers. For the auto-generated share image still to come, the approach is recorded but not yet built: Next's built-in image-response renderer on the Node runtime, with one caveat — its underlying engine needs a static-weight font, so the variable brand woff2 will need a static export or fallback face when that route is written.

Each post page now emits a full head instead of just title and description. A shared buildPostMetadata helper produces the canonical URL, an article-typed Open Graph block (title, description, published/modified times, author, resolved image) and the matching large-image Twitter card, all off the single canonical-host source. The page also renders BlogPosting JSON-LD with the author from the team registry, the dates, the image, and the canonical URL, so search engines get structured article data. Heading anchors come from adding rehype-slug to the markdown pipeline; since the sanitize schema rewrites ids to a user-content- prefix via its clobber list and this markdown is studio-authored, the schema drops id from clobber so anchors stay clean for fragment links. Two save-time guards were added to the admin create/update routes: slugs must round-trip through slugify (lowercase, hyphen-separated, no spaces or punctuation) and every image must carry non-empty alt text, both rejected with a 400.

Co-located tests cover the metadata and JSON-LD helpers, the slug and alt-text validators, the new 400 paths on both admin routes, and clean heading ids from the renderer. The full suite, lint, and production build pass, and a live post confirmed the per-post image, article tags, JSON-LD, and anchors render.
