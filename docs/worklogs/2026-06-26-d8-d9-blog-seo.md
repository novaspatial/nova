# Blog image decisions and per-post SEO metadata

Date: 2026-06-26

Goal: give every blog post a full search and social presence — canonical URL, Open Graph, Twitter card, structured data, heading anchors — after settling where a post's images come from.

Image decisions: the hero and social image is simply the first image in the post body (via the existing extractHeroImage), falling back to the site-wide default — no new database column or editor field, and resolvePostOgImage keeps an explicit fallback chain so a dedicated column could be added later without reworking callers. The auto-generated share image is decided but not built: Next's image-response renderer on the Node runtime, with 1 caveat — it needs a static-weight font, so the variable brand woff2 needs a static export or fallback face first.

Each post page now emits a full head via a shared buildPostMetadata helper — canonical URL, article-typed Open Graph block, matching large-image Twitter card, all off the single canonical-host source — plus BlogPosting JSON-LD with the author from the team registry, the dates, the image, and the canonical URL. Heading anchors come from rehype-slug; since this markdown is studio-authored, id was dropped from the sanitize schema's clobber list so anchors stay clean for fragment links. 2 save-time guards on the admin create/update routes reject with 400: slugs must round-trip through slugify, and every image must carry non-empty alt text.

Tests cover the metadata and JSON-LD helpers, both validators, the new 400 paths, and clean heading ids. Suite, lint, and production build pass; a live post confirmed the per-post image, article tags, JSON-LD, and anchors render.
